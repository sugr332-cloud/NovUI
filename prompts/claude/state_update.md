【作業】章 {{chapter_id}} の状態更新のうち、章終了時点の状態の要約（summary）を作ってください。

上の資料のうち、chapters/{{chapter_id}}/draft.md が要約する本文、chapters/{{chapter_id}}/plan.yaml がこの章の執筆計画、chapters/{{chapter_id}}/outline.md が Human の書いた章の概要です。その他の資料は、本文を書き、検証したときと同じ版です。本文の `<!-- scene: S1 -->` のような行は場面の区切りで、本文の一部ではありません。この章の場面の ID は {{scene_ids}} です。

この要約は、Human の承認を経て chapters/{{chapter_id}}/summary.yaml となり、次の章を書くときの前提になります。したがって、**本文に書かれたことだけ**を、正確に、簡潔に記録してください。

* 本文に書かれていないことを書いてはいけません。本文から確実に読み取れないこと、あなたの推測、今後の展開の予想は書かないでください。
* 資料（characters/、world/ など）に書かれている既存の内容を、そのまま繰り返す必要はありません。この章で**新しく分かったこと・変わったこと**を書いてください。
* 本文に反して設定を正したり、本文の誤りを直したりしてはいけません。本文と設定が食い違って見えても、ここでは本文に書かれていることを記録します（食い違いの判断は別の検査で行います）。

各項目の書き方：

* type：`summary`
* chapter_id：`{{chapter_id}}`
* events：この章で起きた出来事を、起きた順に1件ずつ、1文で。場面の ID（S1 など）を文頭に書いてください（例：`S2 門番がカイの紋章に反応し、カイは門を通る`）。1件以上必須です。
* characters：本文に登場した人物のうち、**資料に `characters/<ID>.yaml` がある人物**だけを、人物 ID（{{character_ids}} のいずれか）で1人1件。名前のない端役や、資料にない人物は含めません。重複させてはいけません。各件の項目は次のとおりです（すべて必須で、該当がなければ null か空の配列にします）。
  - id：人物の ID。
  - location：章の終わりの時点での居場所。本文から分からなければ null。
  - knowledge_added：この章で**その人物が新しく知った**事実を、1件1文で。その人物が見聞きしていない事実（他の人物だけが知っていること、読者だけが知っていること）は入れません。characters/ の knowledge にすでにある事実は入れません。
  - items_gained、items_lost：この章で手に入れた物・失った物（名前は本文にある語で）。
  - condition：章の終わりの時点での負傷・疲労・心身の状態。特記することがなければ null。
  - relationship_changes：この章で変わった他の人物との関係。with は相手の人物 ID（資料にある ID）、change は何がどう変わったかを1文で。変化がなければ空の配列。
* world_impacts：この章で明らかになった、または変わった世界の事実（場所・組織・しくみ・出来事など）を1件1文で。設定そのものを決めたり、設定を変更する提案を書いたりしてはいけません。本文に書かれた事実の記録だけです。なければ空の配列。
* foreshadowing：この章の本文が扱った伏線を、伏線 ID（{{foreshadow_ids}} のいずれか）で1件ずつ。plan の場面が扱うとされた伏線と、本文が実際に扱った伏線の両方が対象です。各件は次のとおりです。
  - id：伏線の ID。資料にない ID を作ってはいけません。
  - status：この章の終わりの時点での状態。`planned`・`active`・`resolved`・`cancelled` のいずれか。registry.yaml の現在の status を出発点にし、本文がそれを変えている場合だけ変えてください。`resolved` にするのは、本文でその伏線が明確に回収されている場合だけです。`cancelled` にしてはいけません（取りやめは Human が決めます）。伏線を「回収すべき」かどうかをあなたが決めてはいけません。
  - note：本文のどこでどう扱われたかを、場面の ID から始めて1〜2文で（例：`S2 門番が紋章に反応する。理由は明かされない`）。ヒント・展開・導入・回収のどれに当たるかが分かるように書いてください。
* next_start_state：次の章の冒頭の時点の状況を、1〜3文で。次の章の本文を書く人がこれだけ読んで場面を始められるように、誰がどこにいて、何が起きた直後かを書いてください。今後の展開は書きません。

summary 以外のものを出力してはいけません。人物や伏線の設定ファイルを変更する提案は、この後の別の作業で行います。ここでは書かないでください。
