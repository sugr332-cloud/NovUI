## 1. 実装したもの（ファイルと関数）

### 修正ファイル
1. **`src/novui/directedit.py` (`direct_edit`)**
   - **R1 対応（編集失敗時の作業ツリー整合性保護）**:
     - 章状態変更処理（ステップ 5）において、更新予定の `chapter.yaml` の内容（dict）をすべてメモリ上で作成し、schema および semantics（`validate_or_raise`, `check_chapter`）の事前検証を完了するように変更。この段階では作業ツリーにも作業ブランチにも書き込まない。
     - メモリ上での全検証が通った後、作業ブランチのある後続章への `mark_review_required(..., branch_only=True)` を実行。
     - その後 main の `chapter.yaml` を書き込み（`write_yaml_atomic`）、単一コミット（`commit_all`）を実行。
     - 書き込みまたは commit 処理中に例外が発生した場合は、書き込まれた `chapter.yaml` を元の中身（`orig_chapter_yamls`）へ復元し、`git reset -q` で index を戻す。
     - 途中でどのような失敗（後続章の作業ブランチに RUNNING の Job がある場合の `ChapterError` など）が発生しても、Human が編集したファイル（`draft.md` 等）は作業ツリーにそのまま残り、`chapter.yaml` は変更されない。

2. **`src/novui/impactjob.py` (`run_impact_job`)**
   - **R2 対応（過去の編集コミットに対する影響分析の再実行許可）**:
     - `head` コミットの検証条件を「main の HEAD と完全一致」から「main の HEAD またはその祖先」（`git merge-base --is-ancestor head main`）に変更。祖先でない場合は `ValueError` を送出。
     - 差分は今までどおり `<head の親>..head` 間の保護対象ファイルの差分（unified diff）を抽出し、要確認フラグは現在の main（および作業ブランチ）の `chapter.yaml` に設定する設計を維持。
     - これにより、edit の後の影響範囲分析が失敗し、Human が先に別のコミットを積んだ場合でも、後から `analyze-impact --commit <edit の commit>` を再実行して回復可能となった。
