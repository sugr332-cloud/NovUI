# Phase 3-A 作業報告：main への commit の保護と要確認フラグ

## 実装したもの（ファイルと関数）

1. `src/novui/protectaudit.py`（新規作成）
   - `audit_changes`: 保護対象パス（`protected.is_protected`）の変更に関する共通検査関数。規則1〜6を実装（安全でないパスの検査、保護対象変更なしの即時リターン、`allow_edit=True` 時の `NovUI-Edit` trailer 許容、`Approval-Id` trailer の有無、各承認記録の検証（形式、同一commitでの追加、schema・semantic、approval_id一致、`job_id` が null でない場合の `NovUI-Job` trailer 照合、`is_used` 検査）、`.novui/approvals/` 配下の変更・削除禁止・targets 照合）。

2. `src/novui/workrepo.py`
   - `commit_all`: index（stage された変更）に対する検査を従来の簡易的な `check_commit_guard` から `audit_changes(..., allow_edit=True)` に差し替え。初回 commit 等で HEAD が無い場合にも対応。違反時は `git reset -q` して関連する保護対象パスを含む `CommitGuardError` を送出。

3. `src/novui/finalize.py`
   - `audit_protected_changes`: 各 commit の保護対象変更検査を `audit_changes(..., allow_edit=False)` を呼び出す形に書き換え、元の文言形式 `<commit[:10]>: <violation>` を維持。
   - `final_approve`: main の chapter.yaml がすでに FINAL（FINAL の章を開き直したサイクル）の章を最終承認する際、後続の全章に `previous_chapter_changed`（detail: `<章> was changed and final-approved again`）の要確認フラグを付与する処理を追加。後続章のうち作業ブランチがある章は merge 前に `mark_review_required(..., branch_only=True)` を呼び出し、作業ブランチのない章は `review_marked` で生成したメタデータを merge の `extra_writes` に追加。

4. `src/novui/chapters.py`
   - `review_marked`: 純粋関数。元の dict を変更せずに `review_required=True` とし、理由 `{code, detail, at}` を追加。同一 code・detail の既存理由がある場合は重複追加せず `at` も維持。
   - `subsequent_chapters`: `chapters-order.yaml` の順序において指定章より後続の章一覧を取得（章が存在しない場合は `ValueError`）。
   - `mark_review_required`: 対象章に要確認フラグを立てて commit。作業ブランチがある章は各 worktree で1章ごとに commit（subject: `review required <章> (<code>)`）、作業ブランチのない章は `branch_only=False` の場合に main でまとめて1つ commit（subject: `review required <章,章,...> (<code>)`）。作業ブランチの章に RUNNING / CHECKING / VALIDATING の Job があれば事前に一括検査して `ChapterError`（何も書き込まない）。
   - `clear_review_required`: 対象章の要確認フラグを下ろして commit（subject: `review done <章>`）。作業ブランチがあれば worktree で、なければ main で更新。すでに False の場合は `ChapterError`。

5. `src/novui/cli.py`
   - `review-done --work <key> --chapter <id>` サブコマンドを追加（`clear_review_required` を呼び出して commit を表示）。
   - `show` サブコマンド（`--chapter` なし）：作業ブランチがある章は作業ブランチの `chapter.yaml` を参照し、要確認フラグが立っている章の行末尾に ` (review required)` を付与し、その直下に理由を `  - <code>: <detail> (<at>)` 形式で表示。

6. テストファイル（新規追加）
   - `tests/test_protectaudit.py`: 規則1〜6の単体テスト、`job_id` が null の instruction 承認記録の許容、非 null 時の `NovUI-Job` 要求、および `commit_all` の (a)〜(e) の挙動（`NovUI-Edit` による保護対象変更の許容、有効な記録と `Approval-Id`、記録なし、targets 外、使用済み id での `CommitGuardError` と index クリーン / HEAD 維持）を検証。
   - `tests/test_review_required.py`: `review_marked`、`subsequent_chapters`、`mark_review_required`（main のみ / 作業ブランチのみ / 混在 / active job 拒否 / order 外拒否 / branch_only）、`clear_review_required`、`final_approve`（初回の FINAL での後続不変更、再オープンサイクルでの後続章要確認付与、要確認による最終承認ブロック、review-done 後の正常 merge / overlap 回避）、CLI `review-done` および `show` の表示を検証。
