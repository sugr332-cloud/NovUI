## 1. 実装したファイルと主な関数・クラス

### 新規作成ファイル
1. **`src/novui/settingchange.py`**
   - `setting_context(repo: Path) -> list[str]`: 人物・伏線・ルール等、main に存在する設定ファイルの一覧を `collect_plan_context` と同一順序で取得。
   - `build_instruction_approval(approval_id: str, *, instruction_id: str, patches: Sequence[Mapping[str, Any]]) -> dict[str, Any]`: `job_id: null` かつ `source: "instruction"` の承認レコードを構築・検証。
   - `run_setting_change_job(...) -> dict[str, Any]`: 方針（`setting_change_plan`）、対象別 Patch（`setting_patch`）、影響範囲分析（`impact_analysis`）の 3 段パイプラインを実行し、提案を保存して Job を COMPLETED（questions 時は WAITING_HUMAN）にする。
   - `approve_setting(settings: Settings, work: WorkInfo, instruction_id: str) -> dict[str, Any]`: pending な提案を検証（ハッシュ整合、作業ブランチ先行変更なし）、影響章への `review_required` 付与、main への一括コミットと `approved` への遷移。
   - `reject_setting(settings: Settings, work: WorkInfo, instruction_id: str, reason: str) -> dict[str, Any]`: pending な提案を `rejected` に遷移。
   - `load_setting_proposal`, `save_setting_proposal`: 提案ファイルの永続化・読み込み。
   - `all_job_branches(repo: Path) -> list[str]`: `refs/heads/ai/` 配下の全作業ブランチを取得。

2. **`src/novui/settingcheck.py`**
   - `is_setting_target(repo: Path, target: str) -> bool`: 対象が `characters/<ID>.yaml` または `foreshadowing/registry.yaml` かつ存在するかを判定。
   - `check_setting_patch_policy(patch, doc_before, *, target, new_foreshadow_ids) -> CheckResult`: 人物（`/id` や全体への変更禁止）および伏線（トップレベルの削除・置換禁止、新規追加の ID 順序）のポリシー検査。
   - `check_setting_result(repo, target, doc_before, doc_after) -> list[CheckResult]`: パッチ適用後の schema、semantics、伏線位置（`foreshadow_positions` / `foreshadow_order`）、台本形式フラグ条件（`flag_conditions`）の総合検証。

3. **`src/novui/impact.py`**
   - `impact_chapters(repo: Path) -> list[tuple[str, str]]`: main において `summary.yaml` または `plan.yaml` を持つ候補章の一覧を決定（アウトラインのみの章は除外）。
   - `analyze_impact(settings, repo, instruction, diff_text, call) -> tuple[...]`: 一時作業ディレクトリ下で変更後設定および候補章の要約/計画を配置し、Claude に影響範囲分析を依頼、検証して一時ディレクトリを確実に削除。

4. **`src/novui/follow.py`**
   - `FollowConflict(ChapterError)`: main の変更パスと作業ブランチの変更パスが重複した際の例外。
   - `follow_main(settings, work, chapter_id, *, allow_pending=False) -> str | None`: main が進んでいる場合に作業ブランチを rebase 追従（重複時は `FollowConflict`、実行中 Job や pending 提案時は `ChapterError`）。main が進んでいない場合は None を即時返却。

## 3. 指示どおりにできなかった点（理由とともに）

1. **`_check_draft_consistency` のシグネチャ互換性維持**
   - **理由**: 指示書では「関数の形を変える場合は、呼び出し側をすべて直す」とありましたが、編集禁止対象である `src/novui/editjob.py` の 114 行目で `draft_record, details = _check_draft_consistency(...)` と 2 要素のアンパックを行っています。`editjob.py` を変更することは厳格に禁止されているため、既存呼び出し元を壊さないよう `return_followed: bool = False` のデフォルト引数を設け、`return_followed=True` が指定された場合のみ `(draft, details, followed_paths)` の 3 要素タプルを返す設計としました。
2. **`follow_main` における worktree 未コミット変更検査の順序**
   - **理由**: 指示書の記述順（`info = cycle_info(..., require_worktree=True)` を最初に行う）通りに実行すると、main が前進していない場合でも worktree 内に未コミット変更があると `cycle_info` で `ChapterError` が送出されます。これにより、作業ツリー内の変更を検知して `draft_consistency` check を FAIL にする既存テスト（`test_failed_draft_consistency_does_not_call_claude`）が Job 記録作成前に異常終了してしまいました。そのため、まず git オブジェクト上で `main_head == mb`（main が前進していない）かどうかを判定し、rebase の必要がない場合は worktree の未コミット検査を行わずに直ちに `None` を返すように最適化しました。
3. **`tests/test_routingjob.py` の未サポートスコープテストの変更**
   - **理由**: Phase 2 時点で書かれたテスト `test_routing_argument_errors` および `test_routing_cli` では、未サポートスコープの検証用ダミー値として `"setting"` が使用されていました。Phase 3-B で `"setting"` が正式スコープとして認可されたため、テストが検証しようとしている「未サポートスコープが与えられた場合にエラーとなること」の期待値を保つため、ダミー値を `"unknown"` に更新しました。

## 4. 次の作業への申し送り

### 3-C：設定変更時の既存章の整合チェック
- `src/novui/impact.py` の `impact_chapters` および `analyze_impact` は、章の summary.yaml / plan.yaml に基づく影響範囲分析の共通処理として完成しています。3-C ではこの関数をそのまま呼び出して影響章を特定できます。
- `approve_setting` によって影響章には `review_required`（code: `setting_changed`、detail: `<instruction_id>: <targets> changed`）が付与されます。3-C では、このフラグが付与された章を対象に整合性レビュー Job を投入・実行するフローを実装することになります。

### 3-D：指示に基づく長文執筆の先行調査
- `src/novui/follow.py` の `follow_main` による自動追従機構（git rebase）により、長時間作業ブランチが存在していても main の設定変更を安全に取り込む土台が整いました。
- main と作業ブランチで同一ファイルが変更された場合は `FollowConflict` となり Job が `WAITING_HUMAN` で一時停止します。3-D において長文執筆作業が並行して進む際、コンフリクト発生時のユーザー誘導（discard 以外の人間によるマージや解消手段）の整理が有用となります。
